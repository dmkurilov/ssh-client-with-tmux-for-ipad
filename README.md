# ssh-client-with-tmux-for-ipad

An iPad-only SSH client that delivers an iTerm2 + tmux `-CC` experience.

> **Status:** early development. Domain parsing modules (`SSHConfig`,
> `TmuxCC`, `ColorSchemes`) are in place and tested. The iPad app
> target is scaffolded but the UI is a placeholder; SSH connection,
> terminal rendering, and onboarding modules are still to come.

## What this is (v1 scope)

- SSH client, not a local terminal.
- Full OpenSSH `ssh_config` grammar with `Include`, `Host`, `Match`,
  `ProxyJump`, token expansion.
- Password and public-key auth. Keys in iOS Keychain behind Face ID.
- iTerm2-style hotkeys, fully remappable. External keyboard first,
  on-screen mode with iSH-style extra key row optional.
- Tabs + splits via tmux `-CC`. User connects, then types
  `tmux -CC attach` manually (auto-attach is a later TODO).
- Color schemes, including `.itermcolors` import.
- Session transcript logging, exposed via the iPad Files app.
- URL scheme `ssh://user@host`.

See `docs/01-product-brief.md` for the complete v1 scope and
`docs/02-design-proposal.md` for stack decisions.

## Repository layout

```
Package.swift              -- SPM manifest for all domain modules
project.yml                -- xcodegen config for the iPad app target
Sources/
  SSHConfig/               -- OpenSSH ssh_config parser + resolver
  TmuxCC/                  -- tmux -CC protocol parser
  ColorSchemes/            -- .itermcolors importer + built-ins
  SSHCore/                 -- Citadel wrapper, connection pool (planned)
  TerminalKit/             -- SwiftTerm wrapper + input view (planned)
  OnboardingKit/           -- spotlight overlay (planned)
Tests/
  SSHConfigTests/
  TmuxCCTests/
  ColorSchemesTests/
App/
  Sources/                 -- SwiftUI app entry + views
  Resources/               -- Info.plist (generated), Assets.xcassets
docs/                      -- product brief, design, conversation log
```

A single root `Package.swift` with multiple library products is used
(one target per module) rather than separate packages per folder. Same
modularity, simpler CI, one `swift test` to cover everything.

## Requirements

- **Client**: iPadOS 17+.
- **Build**: Swift 5.9+ (Xcode 15+).
- **Remote server**: tmux 3.2+ (for a complete `-CC` control-mode
  protocol). Older versions are unsupported.

## Building

### Domain modules (Swift Package Manager)

```bash
swift build
swift test
```

Builds and tests the pure-Swift modules (`SSHConfig`, `TmuxCC`,
`ColorSchemes`) on Linux or macOS — no Xcode required.

### iPad app

The iOS app target is described in `project.yml` and generated by
[xcodegen](https://github.com/yonaskolb/XcodeGen). Both
`SSHClientTmux.xcodeproj/` and `App/Resources/Info.plist` are
gitignored — `project.yml` is the source of truth.

```bash
brew install xcodegen              # one-time
xcodegen                           # regenerate the Xcode project
open SSHClientTmux.xcodeproj
```

In Xcode: select the `SSHClientTmux` target → **Signing &
Capabilities** → pick your Apple ID as the Team (change
`PRODUCT_BUNDLE_IDENTIFIER` in `project.yml` if the default collides).
Choose an iPad simulator destination and ⌘R to run. On first run the
app shows a scaffold screen confirming the SPM wiring is working.
